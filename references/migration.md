# 재작성과 점진 전환

느린 구조를 고치려고 렌더링 방식이나 프레임워크를 바꿀 때의 진행 방법이다. 핵심은 기존 시스템을 명세로 삼고, 조금씩 옮기고, 언제든 되돌릴 수 있게 하는 것이다.

## 1. 기존 시스템이 명세다

새 서버는 기존 서버가 하던 일을 빠짐없이 해야 한다. 문서보다 실제 응답이 정확하다. 다음을 테스트로 고정한다.

- URL 정리 규칙: 끝 슬래시, 대소문자, 중복 슬래시, 기본 파라미터(`?page=1`) 처리
- 리다이렉트: 상태 코드(301, 302, 308)와 `Location`
- 404와 410: 없는 글, 삭제된 글, 비공개 글의 응답
- 메타 태그: `<title>`, description, canonical, robots, Open Graph, Twitter 카드, hreflang
- 구조화 데이터: JSON-LD의 `@type` 목록과 주요 필드

## 2. parity 검사

`scripts/parity.mjs`는 같은 경로를 두 서버에 요청해 위 항목을 비교하고, 다른 경로만 표로 보여준다. 차이가 있으면 종료 코드 1이라 CI에 바로 넣을 수 있다.

```bash
# 경로 목록: 실제 트래픽 상위 경로 + 리다이렉트/404 같은 경계 사례
cat > paths.txt <<'EOF'
/
/post/123
/post/123/
/old-path
/does-not-exist
EOF
node scripts/parity.mjs --a https://old.example.com --b https://new.example.com --paths paths.txt
node scripts/parity.mjs --a https://old.example.com --b https://new.example.com --paths paths.txt --ua googlebot
```

경로 목록은 접근 로그 상위 경로, 사이트맵 표본, 과거 장애가 난 경로로 만든다. 크롤러 User-Agent로도 돌려 크롤러용 응답(2MB 이하)을 함께 확인한다. 정규식 기반이라 JS가 만드는 태그는 보지 못한다(파싱 한계는 스크립트 주석 참고).

## 3. 점진 전환 순서

1. **크롤러와 비로그인 트래픽 먼저.** 상호작용이 적고, 문제가 생겨도 계정 데이터가 걸리지 않는다. 캐시 효과도 가장 크다.
2. **로그인 사용자는 그룹 단위로.** 국가, 사용자 비율, 내부 직원 순으로 넓힌다.
3. **엣지에서 경로별로 라우팅한다.** 새 앱이 처리하는 경로만 새 서버로 보내고 나머지는 기존 서버로 보낸다. CDN 규칙, Worker, 리버스 프록시 설정으로 한다.
4. **기능 스위치로 즉시 되돌린다.** 배포 없이 라우팅을 기존 서버로 돌릴 수 있어야 한다. 되돌리는 절차를 미리 연습한다.
5. **첫 그룹은 A/B로 비교한다.** 같은 기간 실제 트래픽에서 제품 지표, Core Web Vitals, 오류율, 전환율을 비교한다.

## 4. 공통 기능 공유

두 앱이 함께 도는 동안 결제, 채팅, 알림 같은 공통 기능을 두 번 만들지 않는다. 공유 패키지(모노레포)나 Module Federation으로 한 구현을 양쪽에서 쓴다. X는 Money, X Chat, Calls를 Module Federation으로 불러오며, Money 첫 페이지가 590KB에서 509KB(gzip)로 줄었다.

## 5. AI 에이전트로 진행할 때

**AGENTS.md 공통 규칙.** 저장소 루트에 두고 모든 에이전트가 읽게 한다. 예:
- named export만 쓴다. default export 금지.
- barrel 파일(`index.ts`에서 재수출 모음) 금지. 번들 분석과 트리 셰이킹을 망친다.
- 외부 데이터(API 응답, 사용자 입력, 환경 변수)는 신뢰 경계에서 스키마로 검증한다.
- 린트, 타입 검사, 관련 테스트가 통과하기 전에는 커밋하지 않는다.

**반복 작업은 스킬로.** 커밋, PR 생성과 리뷰, CI 통과 확인, 의존성 변경, 번역 키 추가처럼 매번 같은 절차는 저장소 안 스킬로 둔다. X는 25개 이상을 두었다.

**커스텀 린트로 anti-slop 규칙.** 에이전트가 자주 만드는 패턴을 린트 규칙으로 막는다.
- 연쇄 타입 단언 (`x as unknown as Foo`)
- `unknown` 타입 파라미터로 검증을 건너뛰는 함수
- 빈 객체 조건부 spread (`...(cond ? { a } : {})`)

oxlint나 ESLint 커스텀 규칙으로 만든다.

**훅.** pre-commit에서 포맷, 린트, 타입 검사를 하고, pre-push에서 영향받는 패키지의 테스트를 돌린다.

**사람이 할 일.** 시스템이 어떻게 동작해야 하는지 결정하고, 실제 브라우저와 느린 망에서 결과를 확인한다. parity 검사와 성능 비교 결과를 리뷰한다.
